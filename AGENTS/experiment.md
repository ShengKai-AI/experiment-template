# 实验模式

## 身份与目标

实验模式负责实验计划、配置、运行、监控和结果汇报。目标是保证计划配置、实际执行、代码版本、阶段输入输出和实验结果能够相互对应。

## 开始实验工作前

1. 阅读 `experiments/example.yaml`、`runs/example.yaml` 以及任务相关的真实配置和 Run。
2. 检查当前代码版本、工作区状态和是否存在未完成运行。
3. 明确实验目标、对照关系、关键参数、评测方法和完成条件。
4. 区分本次工作是计划、配置、执行、监控还是结果汇报。

## 参数要求

- 已有配置明确给出的参数可以直接使用。
- 未经用户或已有配置明确指定时，不得自行决定会影响实验语义或可比性的设置，包括实验目标、对照关系、模型、数据、随机种子、训练与推理参数、预算、评测方法和指标。
- 可以自行处理不改变实验语义的 ID、时间戳、日志名、输出路径和格式整理。

## Experiment 管理

- 主实验、基线和消融配置分别存放在 `experiments/main/`、`experiments/baselines/` 和 `experiments/ablations/`。
- `experiments/example.yaml` 仅用于展示结构，不得作为真实实验配置使用。
- Experiment 使用固定的 `experiment` 信息和项目自由定义的 `spec`，详细形式以示例文件为准。
- Experiment 记录计划执行的内容，不记录某次运行的动态状态。
- 正式运行前不得保留会影响执行的未确认占位值。
- 已被 Run 使用的 Experiment 如果发生语义变化，必须增加版本或创建新配置；不得静默改变历史含义。

## Run 与 Execution 管理

- `runs/example.yaml` 仅用于展示结构，不得改写为真实运行记录。
- 真实 Run 存放在 `runs/<run_id>/run.yaml`，一般使用时间戳和简短名称组成 `run_id`。
- Run 必须记录时间、状态、Git commit、分支、工作区状态以及包含的所有 Execution。
- 每个 Execution 必须引用源 Experiment，并保存开始执行时实际使用的完整 `config_snapshot`。
- 创建快照时，应先应用已经确认的参数调整；差异同时记录在 `adjustments` 中。
- Execution 开始后不得静默修改 `config_snapshot`。改变实验语义时创建新的 Execution；恢复性或操作性调整可以保留在原 Execution，但必须追加记录。
- Run、Execution 和 Stage 的状态必须反映实际情况，不能只根据计划、进程存在或局部日志将其标记为完成。

## Stage 与监控

- Stage 的名称和结构由具体项目定义，预计阶段优先在 Experiment 中声明。
- 每个实际 Stage 应记录状态、时间、实际命令、输入、输出、日志和必要指标；不适用的字段可以省略。
- 关键数据、模型和结果应记录明确路径，并在可行时记录版本、commit 或哈希。
- Stage 开始和结束时应及时更新记录；没有生成必需输出的 Stage 不得标记为完成。
- 运行时新增 Stage 时，必须记录新增原因。
- 汇报进度时，应说明最近完成的阶段、当前阶段、已有产物和异常。

## 实验日志

- 正式 Run 进入 `completed`、`failed` 或 `cancelled` 终态后，使用 `AGENTS/templates/experiment-log.md` 创建 `runs/<run_id>/experiment-log.md`。
- 每个 Run 只生成一份实验日志；一个 Run 包含多个 Execution 时，在同一日志中汇总。
- 实验日志按 Run 生成，不按对话次数、Stage 数量或自然日生成。长时间运行期间只持续更新 `run.yaml`。
- 冒烟测试、工程测试和调试运行不生成正式实验日志。
- 实验日志应简要说明实验目标、实际执行内容、关键设置与调整、结果、结论、异常和产物；完整配置与阶段细节引用同目录的 `run.yaml`，不重复抄写。
- 后续补充或修正同一 Run 的结果时，更新原实验日志的 `updated_at` 和相关内容，不创建重复日志。

## 模式边界

- 实验模式不进行与当前实验无关的架构调整或大规模代码重构。
- 实验中发现必须修改代码的问题时，先记录对当前 Run 的影响，再切换到工程模式处理。
- 代码发生可能影响实验结果的修改后，应基于新的 commit 创建新的 Execution。

## 结果汇报

- 汇报实际指标、评测条件、对照关系、结果路径以及异常或缺失情况。
- 实验失败、暂停或结果不完整时，应说明当前状态和原因。
- 分别说明哪些内容已经完成、正在运行和尚未开始。
